# Copywriting policy

Interface copy must help a person understand a capability, choose a path, or
complete an action. This policy is a project default for Ruseact Example, not a
ban on voice or editorial writing.

## Rules

- Use sentence case for headings, labels, buttons, navigation, and ordinary
  interface copy. Preserve legitimate acronyms, code, identifiers, protocol
  names, and technical data.
- Name the thing plainly: 'Preview', 'Source', 'Runtime state', 'Run test'.
- A description must add information, context, consequence, or instruction.
  If it repeats the heading, remove or rewrite it.
- Remove generic marketing vocabulary when it is not supported by a concrete
  capability: 'Unlock', 'Elevate', 'Seamless', 'Revolutionary', 'Experience the
  power', 'A new era', 'Crafted for', and 'Built different'.
- Avoid forced contrasts, three-part slogans, decorative section intros, and
  multiple labels for one fact.
- Do not invent metrics, adoption claims, compatibility claims, or speed claims.
- Prefer one direct action verb per control. Do not use a slogan as a button.
- Preserve technical meaning and factual caveats; anti-slop review is not a
  license to simplify away important limits.

## Review questions

1. What user decision or action does this text support?
2. Could the user understand the state without the decorative phrase?
3. Does the description add information not already present?
4. Is the wording accurate against the implementation and tests?
5. Is any emphasis semantic, or is it just a visual habit?

## Examples

| Avoid | Prefer |
|---|---|
| EXPERIENCE THE POWER OF REACTIVITY | Preview or remove |
| 01 / THE EXPERIMENT | Runtime state |
| LIVE REACTIVE EXPERIENCE | Preview |
| EXPLORE THE SOURCE | Source |
| A closer look at what is happening | Runtime state |

These examples are policy examples, not claims that every existing page should
be rewritten in this task.
