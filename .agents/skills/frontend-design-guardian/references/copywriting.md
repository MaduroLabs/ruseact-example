# Copywriting for Ruseact Example

Write for a developer deciding whether to understand and try an experimental
framework, not for a generic marketing funnel.

- Lead with what the visitor can observe or run.
- Name the Ruseact capability plainly: signals, explicit flush, conditional
  ownership, keyed identity, or native DOM behavior.
- Distinguish verified behavior from an architectural intention or browser
  observation.
- Keep alpha status visible without apologetic filler.
- Prefer concrete verbs (`Open demo`, `Inspect source`, `Toggle branch`,
  `Move item`) over vague promises (`Unlock`, `Transform`, `Experience`).
- Do not claim production readiness, React compatibility, performance
  superiority, automatic scheduling, or universal browser behavior.
- Keep labels short and accessible; put technical nuance in a nearby note or
  documentation link rather than repeating it in every card.

Before changing factual copy, preserve the existing claim unless the user
approved the correction. Record the source or test supporting any new claim.
